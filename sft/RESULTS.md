# Eval-50 结果汇报

> 数字来源:`dashboard/sft.json` 的 `eval50.arms`、`sft/sbatch/*.sbatch` 的实际提交

## 1 评测集是什么

| 项 | 值 |
|---|---|
| 题集 | OSWorld-Verified 的**冻结 50 题**,按域分层抽样,seed 20260815,排除 proxy 题 |
| 打分 | 每题用它自己的 evaluator,0~1 分(部分题给部分分) |
| **缺题算 0 分** | **跑不完的题绝大多数是模型做不成、一直超时到步数上限,所以按 0 计入,分母恒为 50** |
| 采样 | temp 1.0 / top_p 0.95(客户端)+ top_k 20(serve 侧) |
| 步数上限 | 50 |
| 其他 | history 100,image_max 20,sleep 3,无 `OSTG_*` 环境变量;3 个 VM,所有臂同一套脚本 |

### 1.1 这 50 题的域分布

| 域 | 题数 | 占比 |
|---|---|---|
| multi_apps(跨应用) | 12 | 24.0% |
| libreoffice_calc | 7 | 14.0% |
| libreoffice_impress | 7 | 14.0% |
| gimp / os / vs_code | 各 4 | 各 8.0% |
| chrome / libreoffice_writer / thunderbird / vlc | 各 3 | 各 6.0% |

**注意**:OSWorld 用一个叫 `multi_apps` 的域来标"跨应用";**ostg 生成的任务没有这个域**,
它把跨不跨应用编码在**难度**里(**难度 ≥3 即跨应用**),`domain` 字段记的是**主应用**。
按各自口径:评测集跨应用 **24.0%**,训练语料 B/Bs 跨应用 **55.1%**(172/312 轨迹)。
**两张域分布表不能横向对读。**

## 2 术语对照(报告里出现的所有代号)

| 代号 | 白话 |
|---|---|
| **全量微调** | 模型所有参数都参与训练 |
| **LoRA** | 只训练插进每层的小矩阵(秩 32),**基座权重一个都不动**,训完再合并回去 |
| **rich** | 训练时**让模型看到自己过去的推理**(`preserve_thinking=true`) |
| **lean** | 训练时**把历史推理藏起来**,只给动作(`preserve_thinking=false`) |
| **keepthink** | 评测模板:渲染历史时**保留** `<think>` 块 |
| **stock** | 评测模板:OSWorld **官方默认**,渲染历史时把 `<think>` **剥掉** |
| **gb64 / gb128** | global batch —— 攒够多少个样本才更新一次参数 |
| **ep1 / ep2** | 取第 1 / 第 2 个 epoch 结束时的存档,而不是训完的最终存档 |
| **o**(如 gb64o) | 优化器超参**对齐 OpenWebRL**(weight_decay 0.0、adam_beta2 0.999) |
| **B / Bs / q38-v11100** | 三份训练语料的名字,见 §3 |

## 3 一共用到三份语料

同源:教师 **Qwen3.8-27B** 在 ostg 生成的任务上跑出轨迹,checker 判满分才收。
学生模型一律 **Qwen3.5-4B**。

```
教师 rollout
  ├── v11-100 池 ──→ ① q38-v11100
  └── v11-500 池 ──┬→ ② B
                   └→ ③ Bs = B 再屏蔽超长推理目标
```

| # | 语料 | 轨迹 | 样本 | 怎么来的 |
|---|---|---|---|---|
| ① | **q38-v11100** | 69 | 1,196 | 只用 100 题池。基础流程:checker 判满分才收,过滤幻觉动作,末步不处理 |
| ② | **B** | 312 | 5,659 | 100 池 + 500 池合并,流程同上,规模扩到 4.7 倍 |
| ③ | **Bs** | 312 | 5,586 | **就是 B**,唯一改动见下 |

**② 和 ③ 的唯一差别**:B 里有 73 个步骤的推理特别长(超过 2048 token),
Bs 把这 73 个**训练目标**屏蔽掉、不算 loss —— **但这些步仍然留在历史里**,
模型后续照样看得到。轨迹集合完全相同,只差这 73 个样本(占目标 token 的 15.6%)。

**① 和 ②③ 的差别**:处理流程一样,只是覆盖范围从 100 题池扩到两池合并。

## 5 结果

**得分 = 缺题按 0 计入、分母恒为 50。**

| 语料 | 臂 | 这个臂在测什么 | **得分** | 满分题 | 缺题 |
|---|---|---|---|---|---|
| ③ Bs | **Bs-LoRA** | 只训小矩阵、基座不动 | **47.81%** | 23 | 0 |
| ③ Bs | **Bs-gb64** | 屏蔽超长推理目标后的全量微调 | **45.81%** | 22 | 0 |
| ② B | B-gb128 ep2 ⚠️ | 更大的 global batch(128);**3 epoch 从未跑完(六次 OOM),用的是抢救出的 ep2 存档** | 43.81% | 21 | 1 |
| ② B | B-gb64o | 标准配方:batch 64、3 epoch、优化器对齐 | 41.81% | 20 | 3 |
| — | **基座 4B(未微调)** | 对照线 | **39.81%** | 19 | 0 |
| ② B | B-1ep | 只训 1 个 epoch(学习率退火到 0) | 31.81% | 15 | 0 |
| ① v11100 | rich · stock 模板 | 同一份权重,评测时剥掉历史推理 | 30.00% | 15 | 0 |
| ① v11100 | rich · keepthink | 训练给历史推理,评测也保留 | 28.00% | 14 | 0 |
| ① v11100 | rich ep1 | 同上,但只取第 1 个 epoch 的存档 | 27.81% | 13 | 0 |
| ① v11100 | lean · keepthink | 训练不给历史推理,评测保留 | 23.81% | 11 | 0 |

**基座 39.81% 是分水岭:上面 4 个臂超过它,下面 5 个低于它。**

**"得分"和"满分题"为什么对不上**:部分题的 evaluator 给部分分(`conj:"and"` 可以只满足
一部分)。例如 Bs-gb64 满分 22 题(44.0%),得分 45.81%,差额来自拿到部分分的题。

### 5.1 训练配置明细

| 臂 | 微调 | 卡数 × 累积 | global batch | 学习率 | epoch | 优化器 |
|---|---|---|---|---|---|---|
| Bs-LoRA | LoRA 秩32/α64/全线性层 | 16 × 4 | 64 | 1e-4 | 3 | wd 0.0,beta2 0.999 |
| Bs-gb64 | 全量 | 16 × 4 | 64 | 1e-5 | 3 | wd 0.0,beta2 0.999 |
| B-gb128 ep2 | 全量 | 16 × 8 | 128 | 1e-5 | 取 ep2 | 框架默认 |
| B-gb64o | 全量 | 16 × 4 | 64 | 1e-5 | 3 | wd 0.0,beta2 0.999 |
| B-1ep | 全量 | 8 × 4 | 32 | 1e-5 | 1(退火到 0) | 框架默认 |
| rich / lean | 全量 | 8 × 8 | 64 | 1e-5 | 3 | 框架默认 |

`rich` 与 `lean` 除了训练时给不给历史推理,其余**完全相同**。

## 6 单变量归因

### 6.1 同一份语料内(纯训练/评测变量)

**控制质量分三档**:🟢 真单变量 · 🟡 有 1 个附带差异 · 🔴 有多个附带差异,
差值**不能**归给标题里那个变量。

| 控制 | 语料 | 名义变量 | 对照 | 差值 | **同时还变了什么** |
|---|---|---|---|---|---|
| 🔴 | ② B | 1 epoch → 3 epoch | 31.81% → 41.81% | +10.0 | **global batch 32→64**(1节点→2节点)、**warmup 0.05→0.1**、**优化器框架默认→wd 0.0/β₂ 0.999**。共 4 项差异 |
| 🟢 | ① v11100 | 训练时藏起历史推理 → 给它看 | 23.81% → 28.00% | **+4.2** | 无。`rich`/`lean` 除该 flag 外逐项相同 |
| 🟡 | ③ Bs | 全量微调 → LoRA | 45.81% → 47.81% | +2.0 | **学习率 1e-5 → 1e-4**(高 10 倍)。所以不是"步子更小",是**更新被限制在秩 32 子空间** |
| 🔴 | ② B | global batch 64 → 128 | 41.81% → 43.81% | +2.0 | **优化器框架默认 vs 对齐**、且 gb128 用的是**第 2 个 epoch 的存档**而非训完的权重(原因见下) |
| 🟢 | ① v11100 | 评测时保留历史推理 → 剥掉 | 28.00% → 30.00% | +2.0 | 无。同一份权重,只换渲染模板 |
| 🟢 | ① v11100 | 取第 1 个 epoch 存档 → 训满 3 个 | 27.81% → 28.00% | +0.2 | 无。同一次训练的两个存档 |

**🔴 那两行怎么读**:`+10.0` 只能说"1 epoch/小 batch/默认优化器"这一整套
配置比"3 epoch/大 batch/对齐优化器"差 10 个点,**不能说 epoch 数值 10 个点**。
同理 `+2.0` 不能单独归给 batch 大小。要拆开需要补做单变量臂。

### 6.2 跨语料(数据变量)

| 控制 | 变的是什么 | 对照 | 差值 | 同时还变了什么 |
|---|---|---|---|---|
| 🟢 | **屏蔽 73 个超长推理目标**(B → Bs) | 41.81% → 45.81% | **+4.0** | 无。形状/学习率/优化器/epoch 全同 |
| 🔴 | 语料 69 → 312 轨迹 | 28.00% → 45.81% | +17.8 | **卡数、优化器、语料来源池全变**。只能读作"旧配方小语料 → 新配方大语料"的合并效果 |

**`B → Bs` 是全表最干净的数据变量**:形状、学习率、优化器、epoch 全同,
只差 73 个训练目标,值 4 个点。

### 6.3 微调 vs 不微调

- **超过基座**:Bs-LoRA、Bs-gb64、B-gb128 ep2、B-gb64o
- **低于基座**:B-1ep、rich 三个变体、lean

最差的 lean 比基座低 **16 个点**。**配方或数据不对,微调会把模型弄坏。**

## 7 未跑完 / 需注意的臂

| 臂 | 状态 |
|---|---|
| lean · stock 模板 | 只跑了 3 题、缺 47 题。0 填后是 4.00%,**不是有效测量**,不列入对比 |
| B-gb128(全量 3 epoch 版) | 50 题全缺,无结果 |

**B-gb128 为什么只有 ep2 存档**:global batch 128 需要 accum 8,而本训练栈的显存
**正比于梯度累积次数**(实测:accum 4 稳在 131.9 GiB;accum 16 在第 8–13 步死于
~137;accum 32/64 在第 1 步前就死)。**gb128 六次尝试全部 OOM 崩溃**,3 个 epoch
从未跑完;表里那一行用的是崩溃前抢救出来的**第 2 个 epoch 边界存档**。
所以它既不是"训满 3 epoch 的 batch-128 臂",也不是干净的 batch 对照。
死因详录见 `sft/TRAINING.md`(上游 ms-swift issue #5230 同症)。
