# 旧 r5 + 完整交付 v16：候选方案

状态：标准与候选名单。尚未生成或替换训练语料，未独立完成逐项视觉/产物验收。

## 新增 v16 的验收标准

1. 从原始 instruction 独立列出完整义务：所有对象/范围、操作、数值/格式、条件、指定应用或方法、输出路径/命名、保留项及最后画面状态。不能只继承旧判官列出的 requirements。
2. 每项均为 pass，且有能直接支撑该项的证据。partial / inferred / cannot_tell / 缺证据均进入 uncertain，不进入本版本。证据不足不是已证明失败。
3. 每个要求交付的文件都核对路径、名称、真实格式及关键内容。多文件任务逐个验收；只看见一个输出不能放行整条任务。非文件操作同样必须完成。
4. 保存由 agent 在最后一次相关修改之后完成；Save As、覆盖确认、格式确认、导出选项均已结束，最终不能残留未保存修改。evaluator 的事后自动 flush 不算 agent 保存示范。
5. 持久化证据可来自保存后重开/读回目标文件，或明确的应用保存成功状态与对应内容。只有 Ctrl+S、自述 saved、对话框消失、文件名/大小/mtime，不足以证明内容正确。截图无法证明的公式、元数据、隐藏内容或真实格式，需要文件读取/解析证据；没有则 uncertain。
6. 指定应用/操作方式属于 instruction 时必须满足。instruction 未限制方法时，不额外禁止脚本；不擅自添加任务要求。
7. 核对 run/task/episode、引用帧和动作对应；证据来自原执行时状态。旧 v16 无 final_state.json，不能用后来共享 cache 中的文件补作历史证据。
8. SFT 保留完整合格轨迹及保存/确认步骤，核对构建后仍含对应监督。不追加未经执行的保存步骤，不把证据未知标签改成成功。

“100%”是逐要求全过的准入目标，不代表评审无误。旧 r5 按用户要求保持原版；因此不能把此新增 v16 标准自动扩称为整份混合语料已重新验证 100%。

## 当前可确定的候选规模

范围仍为训练曾使用的 554 条 v16。当前旧判官所有要求逐字段 done=yes/evidence=seen 的 283 条中有 50 条按既有 related_apps 规则计为 multi-app。进一步与保存完成线索初筛相交后，有 143 条 / 3,668 样本，其中 multi-app 37 条 / 1,128 样本。额外排除旧 strict 名单中的 2b67da05-eaf5-5bd8-990e-a3987ca75226（45 样本），因为 r2 evidence=partial-seen。

候选筛选仍依赖旧判官清单及其文字证据，尚未满足上文独立 instruction 覆盖、每个产物和最后修改后保存的完整复核要求。因此 **37 是候选 multi-app 数，不是最终验收通过数**。旧判官 inferred 项可以在补齐原始画面证据后重新复核，不视作永久失败。
