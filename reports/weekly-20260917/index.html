3. Can terminal post-training improve computer use?

Motivation

Computer tasks can also be solved with terminal commands. I wanted to test whether a terminal-trained model provides a better starting point for CUA.

Finding

TMAX + CUA SFT did not improve this run: 51 matched tasks passed, versus 61 with the original Qwen-based model.

Experiment: TMAX-9B language weights + original Qwen visual module → the same r5 CUA SFT data and recipe → Verified100.

Initialization → CUA SFTEval image historyPass rateMean score*

The largest drops were in Calc, Writer, and multi-app tasks: three fewer passes in each group.

What this result says

The expected transfer from terminal post-training has not shown up in the current evaluation.

99 scored tasks are matched by task ID. One interrupted Writer task is excluded, rather than assigned zero.

What still needs to be separated

The old run used 20 images / fold 10; this TMAX run used 10 / fold 1. The matching 20 / fold 10 comparison is not included here.

Serving precision and hardware also differ. This is not yet a clean estimate of initialization alone.

Next, look at the actual failures: did the model miss a visual detail, execute the wrong action, or accept an incomplete result?

4. Failure: the right table, inserted in the wrong place

Task: insert a 7-column × 5-row empty table at the existing cursor. Old r5 passed; TMAX failed.

What it did

Closed the document, reopened it, then picked a new cursor position and inserted the table.

Why it failed

The dimensions were correct, but the original insertion point was lost. The saved document has the tables in the wrong order.

What it should have done

Preserve the original cursor, or recover that location before inserting.

Likely failure typeWrong visual target, followed by unsupported state recovery. The screenshot and action confirm the wrong click; attention alone does not explain it.

7. Failure: repeated repair attempts made the document worse

Task: add one blank line between sentences in the first paragraph. TMAX tried multiple repairs, then declared success.

What it did

Repeatedly selected text, deleted it, and retyped the paragraph to repair earlier mistakes.

Why it failed

The final document starts with a leftover sentence fragment and has the paragraphs in the wrong order.

What it should have done

Check the exact selected range, recover a known-good state, and compare the resulting paragraph before making another large edit.

8. Repetitive loop: the explanation changes, the click does not

Task: color three textboxes yellow, red, and green. The same click is emitted at steps 33–37; the run later hits the 50-step limit.

What it did

Kept clicking the previous dialog’s coordinates, even after saying the click missed and the location should change.

Why it failed

The emitted action did not follow the proposed correction. Steps were spent without closing the dialog; the third textbox was still unfinished at the limit.

What it should have done

Detect the unchanged dialog, re-locate the button, or switch to a verified keyboard confirmation.

Likely failure typeRepetition and failure to adapt the action. The mismatch between the written correction and emitted coordinates is directly recorded.

9. Infeasible task: missing hardware is reported as success

Task: switch on Bluetooth. The machine reports that no Bluetooth hardware is available.

What it did

Clicked the apparent switch and claimed Bluetooth was on despite recognizing that the adapter was missing.

Why it failed

A click on a setting did not establish that Bluetooth was available. The response and terminal status treated an unmet prerequisite as completion.

What it should have done

Report the missing hardware and terminate as infeasible under the benchmark’s protocol.

Likely failure typeFeasibility reasoning and success-status selection. The model read the blocking message, so this is not simply failure to see it.

10. Planning failure: browsing consumes the delivery budget

Task: download the first paper and save the title of a paper that cites it in ans.docx.

What it did

Downloaded the PDF, then spent many decisions scrolling through reference sections to verify the citation.

Why it failed

It exhausted the step budget before producing the second required file. Scrolling changed the page, but did not finish the deliverable.

What it should have done

Track both deliverables, use search or direct page navigation, and reserve steps to write and verify the answer file.

Likely failure typeInefficient planning and missing deliverable. This is different from an identical-screen click loop.

11. Evaluation constraint: a terminal solution misses the required pattern

Task: convert all .doc files to PDF at once from the command line. This zero score needs a different interpretation.

What it did

Ran a shell loop that invokes LibreOffice separately for each file.

Why it scored zero

The first evaluator requires a wildcard command pattern in shell history. The recorded check did not find it, so the PDF-content comparison was never run.

What it should have done

Use the requested all-at-once invocation and verify both command execution and output files.

InterpretationA command/protocol mismatch, not evidence that the model could not see the screen or generate any PDFs. Functional equivalence is not established here.
